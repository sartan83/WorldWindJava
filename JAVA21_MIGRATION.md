WorldWind Java now compiles, tests and runs on Java 21 (OpenJDK 21.0.12, Ant 1.10.12, JOGL/GlueGen 2.5.0).

## Phase 0 - Baseline

- Installed OpenJDK 21 (and 11 for the baseline) and Ant 1.10.12.
- `lib-external/jogl-gluegen/get-jogl.sh` failed: every `v2.5.0-rc-20230523` URL now returns HTTP 404 and, because
  `curl -O` had no `-f`, the 404 HTML pages were silently saved as `.jar` files. The jars committed at the repo root are
  already the JOGL 2.5.0 release (`Implementation-Version 2.5-b1533-20230818`), byte-identical to the
  `v2.5.0` deployment.
- Baseline build + tests on JDK 11: green (table above).

JOGL: 2.5.0 supports Java 21 at runtime. Verified by the GL-backed tests passing under Xvfb on JDK 21 and by the demo
below; no `--add-opens` flags or illegal-access warnings were needed. `get-jogl.sh` was bumped from the dead
`v2.5.0-rc-20230523` path to the `v2.5.0` release and now uses `curl -fLO` so download failures fail loudly.

## Phase 3 - Remediation

### Area A - Java 21 API fixes
See the audit table: `CachedDataRaster` (`runFinalization`), `BrowserOpener` (`Desktop`, `exec(String[])`,
no more `com.apple.eio`), Web Start config/manifest removal. No code path had to be gated.

### Area B - `EGM2008` bug fixes (`src/gov/nasa/worldwind/util/EGM2008.java`)
1. **Partial reads**: `offsetFile.read(latByteData)` ignored the byte count; now `readFully`. The seek offset is also
   computed in `long`.
2. **Antimeridian wrap**: the grid covers 0..360 deg with 8640 data columns framed by 2 row markers. For the last
   column (longitude in (-0.0417, 0) deg, i.e. the 0/360 seam of the grid) interpolation read the trailing marker
   (`lonCol + N_ROW_MARKERS/2 + 1`), and `lon = -0.01` even threw `ArrayIndexOutOfBoundsException`. Column indices
   are now wrapped (`getRowDataIndex`, `Math.floorMod` over `N_DATA_COLS`) so the neighbour of the last column is
   data column 0.
3. **Thread safety**: `getLatRows` (cache lookup + `RandomAccessFile` read + cache put) is serialized on a private
   lock, so concurrent `getOffset` calls cannot interleave `seek`/`read` on the shared file.
4. **Null guard**: `latDataArray[0] == null` now returns `0`, mirroring the existing `latDataArray[1]` check.
5. Removed the unused `protected BufferWrapper deltas` field.
6. `getLatRow`/`getLonCol` use `double` and `Math.floor`; `getOffset(Angle, Angle)` no longer narrows to `float`.

### Area C - `EGM2008Offsets` example
The example previously queried the shared `EGM2008` instance from a background thread (placemark elevations) while the constructor thread printed test offsets at the same time. All offset queries now run
sequentially on one worker thread, and placemarks are added to the layer on the EDT. It also prints two locations in
the last grid column as a visible regression check.

## Phase 4 - Tests

- JUnit 4.5 runs the full suite on 21 with no changes (no upgrade needed).
- New `test/gov/nasa/worldwind/util/EGM2008Test.java`:
  - synthetic 4321x8642 data file (so it always runs in CI): interior interpolation, wrap to column 0 at the seam,
    `lon = -0.01` not returning a marker, column index range, 8 threads each querying 2000 random locations, compared with serial results;
  - real-data regressions against `egm2008_25.dat` (path from `EGM2008_DATA`, default `config/egm2008_25.dat`;
    skipped via `Assume` if absent) using the `EGM2008Offsets` coordinates, e.g. `(47,-94) = -28.665308`,
    `(37,-119) = -26.150883`.
- Against the original `EGM2008.java`, 4 of the 8 tests fail (marker value `499775.44` returned at the seam,
  `ArrayIndexOutOfBoundsException` at `lon = -0.01`, column 8640 out of range); all pass with the fix.

## Phase 5 - Full run and demo

- Full `ant -f release-build.xml` on JDK 21 under Xvfb: `BUILD SUCCESSFUL`, 443 tests, 0 failures, 0 errors
  (with `EGM2008_DATA` pointing at the real data file so the real-data tests executed).
- Demo: `./run-demo.bash gov.nasa.worldwindx.examples.EGM2008Offsets` on JDK 21, recorded with `ffmpeg -f x11grab`

## Remaining warnings (not blocking)

- 21 `new URL(...)` deprecation warnings (`-Xlint:deprecation`); the constructors are deprecated but not for removal.
  Migrating to `URI.toURL()` changes exception semantics at each call site and is left for a follow-up.
- 7 pre-existing `-Xlint:unchecked` warnings.
